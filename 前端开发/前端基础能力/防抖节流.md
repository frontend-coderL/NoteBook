亮点：

- 6 种实现方案横评：传统封装 / 函数装饰器 / requestAnimationFrame / AbortController / Web Streams / Lodash
- 现代方案借助原生 API 大幅简化代码，部分场景可一行搞定
- 附带场景选择指南：搜索输入用防抖、滚动渲染用 RAF、流式数据用 Web Streams

## 传统手写版

### 防抖（Debounce）— 延迟执行，最后一次触发才生效

适合搜索输入、表单验证，避免频繁发请求。

```JavaScript
function debounce(fn, delay) {
  let timer = null
  return function (...args) {
    if (timer) clearTimeout(timer)
    timer = setTimeout(() => {
      fn.apply(this, args)
    }, delay)
  }
}

// 使用
const searchInput = document.getElementById('search')
searchInput.addEventListener('input', debounce((e) => {
  console.log('搜索内容：', e.target.value)
}, 300))
```

### 节流（Throttle）— 固定频率执行，单位时间只触发一次

适合滚动加载、窗口 resize，限制执行频率。

```JavaScript
function throttle(fn, delay) {
  let lastTime = 0
  return function (...args) {
    const now = Date.now()
    if (now - lastTime >= delay) {
      fn.apply(this, args)
      lastTime = now
    }
  }
}

// 使用
window.addEventListener('scroll', throttle(() => {
  console.log('页面滚动中')
}, 200))
```

痛点：手动管理定时器/时间戳，代码冗余，复用性一般。

## 现代极简方案

### 方案 1：函数装饰器 — 声明式防抖

TC39 提案的函数装饰器，无需修改原函数，一行注解完成增强。

```JavaScript
function debounce(delay) {
  return function (target, propertyKey, descriptor) {
    const original = descriptor.value
    descriptor.value = function (...args) {
      clearTimeout(this._timer)
      this._timer = setTimeout(() => {
        original.apply(this, args)
      }, delay)
    }
    return descriptor
  }
}

// 使用
class UIUtils {
  @debounce(300)
  static handleInput(e) {
    console.log('处理输入：', e.target.value)
  }
}
```

注意：需 Babel / TS 转译，兼容性有限。

### 方案 2：requestAnimationFrame — 渲染同步极简节流

和浏览器渲染周期同步，视觉操作零卡顿。

```JavaScript
const throttleRAF = (callback) => {
  let ticking = false
  return (...args) => {
    if (!ticking) {
      ticking = true
      requestAnimationFrame(() => {
        callback(...args)
        ticking = false
      })
    }
  }
}

// 使用
window.addEventListener('scroll', throttleRAF(() => console.log('滚动中')))
```

优点：性能最优，适配视觉类操作。局限：仅适合渲染相关场景。

### 方案 3：AbortController — 自带取消机制的防抖

用原生控制器管理取消逻辑，代码更清晰。

```JavaScript
const debouncedFn = (fn, delay = 300) => {
  let controller
  return (...args) => {
    controller?.abort()
    controller = new AbortController()
    setTimeout(() => !controller.signal.aborted && fn(...args), delay)
  }
}

// 使用
const handleSearch = debouncedFn((val) => console.log('搜索：', val))
```

优点：取消逻辑标准化，现代浏览器支持好。

### 方案 4：Web Streams API — 流处理式防抖

面向流的声明式实现，适合流式数据处理场景。

```JavaScript
function createDebounceStream(delay) {
  let timeout
  return new TransformStream({
    transform(chunk, controller) {
      clearTimeout(timeout)
      timeout = setTimeout(() => controller.enqueue(chunk), delay)
    }
  })
}

// 输入框流式使用
async function setup() {
  const input = document.getElementById('search')
  const inputStream = new ReadableStream({
    start(ctl) {
      input.addEventListener('input', e => ctl.enqueue(e.target.value))
    }
  })
  await inputStream
    .pipeThrough(createDebounceStream(300))
    .pipeTo(new WritableStream({ write: val => console.log('搜索：', val) }))
}
setup()
```

注意：API 复杂，兼容性一般。

### 方案 5：Lodash — 零成本开箱即用

```JavaScript
import { debounce, throttle } from 'lodash-es'

// 一行防抖
input.addEventListener('input', debounce(handleInput, 300))
// 一行节流
window.addEventListener('scroll', throttle(handleScroll, 200))
```

优点：简单稳定、经过海量验证。

## 6 种方案横评

| 方案                    | 优点         | 缺点                |
| --------------------- | ---------- | ----------------- |
| 传统封装                  | 兼容性拉满、灵活度高 | 代码冗长、手动管理状态       |
| 函数装饰器                 | 语法简洁、声明式   | 需转译、兼容性差          |
| requestAnimationFrame | 渲染同步、性能极佳  | 仅适配视觉操作           |
| AbortController       | 取消机制清晰     | 现代 API、需 polyfill |
| Web Streams           | 声明式、能力强    | API 复杂、兼容有限       |
| Lodash                | 简单稳定、零学习成本 | 增加依赖体积            |

## 场景选择指南

- 搜索输入框：防抖，避免每输一个字符就发请求
- 窗口 resize：节流，限制布局重算频率
- 无限滚动加载：节流，控制分页请求频率
- 元素拖拽：节流（RAF 首选），保证流畅不卡顿
- 视觉类操作：首选 requestAnimationFrame
