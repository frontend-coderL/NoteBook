### 实时通信三个时代

#### 时代 1：短轮询（Polling）

每隔固定时间发一次请求，无论有没有新数据。

```javascript
// ❌ 短轮询实现
setInterval(async () => {
  const res = await fetch("/api/messages");
  const messages = await res.json();
  renderMessages(messages);
}, 2000); // 每2秒请求一次
```

问题：

- 99% 的请求无效（没有新消息）
- 1000 用户在线 = 每秒 500 次 HTTP 请求
- 实时性差（最坏延迟等于轮询间隔）
- 每次传输完整 HTTP 响应头，浪费带宽

#### 时代 2：长轮询（Long Polling）

客户端发请求，服务器保持连接不响应，直到有新数据才返回。客户端收到响应后立即发起下一次请求。

```javascript
// 客户端
async function longPoll() {
  try {
    const res = await fetch("/api/poll", {
      signal: AbortSignal.timeout(30000) // 30秒超时
    });
    const message = await res.json();
    handleMessage(message);
    longPoll(); // 递归调用，立即发起下一次
  } catch (err) {
    setTimeout(longPoll, 1000); // 出错后重连
  }
}
longPoll();
```

```javascript
// 服务端 Node.js + Express
let waitingClients = [];

app.get("/api/poll", (req, res) => {
  waitingClients.push(res);
  // 30秒超时，返回心跳防止一直等
  setTimeout(() => {
    const index = waitingClients.indexOf(res);
    if (index > -1) {
      waitingClients.splice(index, 1);
      res.json({ type: "heartbeat" });
    }
  }, 30000);
});

function broadcastMessage(message) {
  waitingClients.forEach(res => res.json(message));
  waitingClients = [];
}
```

优势：减少无效请求，实时性接近 0 延迟。
缺陷：服务器需维护大量挂起连接、每次响应后要重新建立连接、多服务器间同步等待队列困难。

#### 时代 3：WebSocket

一次 HTTP 握手升级为持久双向连接。

```
客户端                        服务器
  |--- HTTP升级请求 ----------->|
  |<-- 101 Switching Protocols -|
  |========= TCP连接保持 ========|
  |--- 消息 ------------------->|
  |<-- 消息 --------------------|
  |--- 消息 ------------------->|
  |<-- 消息 --------------------|
  (连接持续开放，双向通信)
```

### WebSocket 实现

服务端（Node.js + ws）：

```javascript
import { WebSocketServer } from "ws";

const wss = new WebSocketServer({ port: 8080 });
const clients = new Map();

wss.on("connection", (socket, req) => {
  const clientId = `user_${Math.random().toString(36).substr(2, 9)}`;
  clients.set(clientId, { socket, connectedAt: Date.now() });

  socket.on("message", (rawData) => {
    const data = JSON.parse(rawData.toString());
    // 广播给除发送者外的所有人
    const msg = JSON.stringify({ type: "chat", from: clientId, text: data.text, timestamp: Date.now() });
    clients.forEach((client, id) => {
      if (id !== clientId && client.socket.readyState === 1) {
        client.socket.send(msg);
      }
    });
  });

  socket.on("close", () => {
    clients.delete(clientId);
    // 通知其他人用户离开
    const leaveMsg = JSON.stringify({ type: "user_left", userId: clientId });
    clients.forEach(client => {
      if (client.socket.readyState === 1) client.socket.send(leaveMsg);
    });
  });
});
```

客户端（带智能重连）：

```javascript
class ChatClient {
  constructor(url) {
    this.url = url;
    this.socket = null;
    this.reconnectAttempts = 0;
    this.maxReconnectAttempts = 5;
  }

  connect() {
    this.socket = new WebSocket(this.url);

    this.socket.onopen = () => {
      this.reconnectAttempts = 0;
      this.onConnected?.();
    };

    this.socket.onmessage = (event) => {
      const message = JSON.parse(event.data);
      this.handleMessage(message);
    };

    this.socket.onclose = () => this.attemptReconnect();
  }

  // 指数退避重连
  attemptReconnect() {
    if (this.reconnectAttempts >= this.maxReconnectAttempts) return;
    this.reconnectAttempts++;
    const delay = Math.min(1000 * Math.pow(2, this.reconnectAttempts), 30000);
    setTimeout(() => this.connect(), delay);
  }

  send(text) {
    if (this.socket?.readyState === WebSocket.OPEN) {
      this.socket.send(JSON.stringify({ text }));
      return true;
    }
    return false;
  }

  handleMessage(message) {
    switch (message.type) {
      case "chat": this.onChatMessage?.(message); break;
      case "user_left": this.onUserLeft?.(message.userId); break;
    }
  }

  disconnect() {
    this.socket?.close();
    this.socket = null;
  }
}
```

### SSE（Server-Sent Events）

只需服务器单向推送、客户端很少发数据时，SSE 比 WebSocket 更简单。

典型场景：实时数据监控（股票、服务器状态）、新闻推送、日志流式输出、排行榜实时更新。

服务端：

```javascript
app.get("/api/stock-stream", (req, res) => {
  // 设置 SSE 响应头
  res.setHeader("Content-Type", "text/event-stream");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");

  // 发送初始数据
  res.write(`data: ${JSON.stringify({ type: "init", stocks })}\n\n`);

  // 定时推送更新
  const interval = setInterval(() => {
    res.write(`data: ${JSON.stringify({ type: "update", stocks, timestamp: Date.now() })}\n\n`);
  }, 1000);

  req.on("close", () => clearInterval(interval));
});
```

客户端：

```javascript
const eventSource = new EventSource("/api/stock-stream");

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  // 处理数据更新
};

eventSource.onerror = () => {
  // 浏览器会自动重连，无需手动处理
};
```

SSE 协议格式：

```
Content-Type: text/event-stream

data: {"type":"init","stocks":{"AAPL":178.32}}\n\n
data: {"type":"update","stocks":{"AAPL":179.15}}\n\n
```

每条消息格式：`data: 内容\n\n`（注意两个换行符）。

### SSE 事件格式详解

每条 SSE 消息由以下字段组成，每个字段独占一行：

```
id: 1
event: message
retry: 3000
data: {"content":"hello"}
\n
```

| 字段 | 作用 |
|------|------|
| `id:` | 消息 ID，客户端可通过 `eventSource.lastEventId` 获取，断线重连时自动发送 `Last-Event-ID` 请求头实现续传 |
| `event:` | 事件类型，不指定时默认 `message`；自定义事件需用 `addEventListener` 监听 |
| `data:` | 消息内容，必须以 `\n\n` 结尾 |
| `retry:` | 指定自动重连间隔（毫秒） |
| `:` 开头 | 注释行，客户端忽略，可用于保持连接存活 |

### 断点续传

EventSource 断线后浏览器会自动重连，但默认从头开始接收数据。配合 `id:` 和 `Last-Event-ID` 可实现续传：

```javascript
const server = http.createServer((req, res) => {
  if (req.url === '/stream') {
    res.writeHead(200, {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive'
    });

    // 获取客户端上次接收的消息 ID
    const lastEventId = req.headers['last-event-id'];
    let startIndex = lastEventId ? parseInt(lastEventId, 10) : 0;

    // 发送消息时带上 id
    messages.slice(startIndex).forEach((msg, i) => {
      res.write(`id: ${startIndex + i + 1}\n`);
      res.write(`data: ${JSON.stringify(msg)}\n\n`);
    });
  }
});
```

### EventSource 的局限性与 fetch 替代方案

原生 EventSource 只接受 `url` 和 `withCredentials` 两个参数，存在以下限制：

- 只能使用 GET 请求
- 无法传递请求体（参数只能编码在 URL 中，受 2000 字符限制）
- 无法自定义请求头
- 自动重连机制无法手动控制

使用 `fetch` + `ReadableStream` 可以绕过这些限制：

```javascript
class FetchEventSource {
  constructor(url, options = {}) {
    this.url = url;
    this.options = options;
    this.isActive = false;
    this.lastEventId = null;
    this.eventListeners = new Map();
    this.start();
  }

  async start() {
    if (this.isActive) return;
    this.isActive = true;

    const params = this.lastEventId ? { lastEventId: this.lastEventId } : {};
    const queryString = new URLSearchParams(params).toString();
    const requestUrl = queryString ? `${this.url}?${queryString}` : this.url;

    try {
      const response = await fetch(requestUrl, this.options);
      const reader = response.body.getReader();
      const decoder = new TextDecoder('utf-8');
      let buffer = '';

      while (this.isActive) {
        const { value, done } = await reader.read();
        if (done) break;

        buffer += decoder.decode(value, { stream: true });
        const lines = buffer.split('\n');
        buffer = lines.pop() || ''; // 保留最后一个不完整的行

        for (const line of lines) {
          this.parseEvent(line.trim());
        }
      }
    } catch (error) {
      console.error('FetchEventSource error:', error);
      this.close();
    }
  }

  parseEvent(line) {
    if (!line || line.startsWith(':')) return;
    const [key, ...rest] = line.split(':');
    const value = rest.join(':').trim();

    if (key === 'id') this.lastEventId = value;
    else if (key === 'event') this.currentEvent = value;
    else if (key === 'data') {
      this.dispatchEvent({
        id: this.lastEventId,
        event: this.currentEvent || 'message',
        data: value
      });
    }
  }

  addEventListener(eventType, listener) {
    if (!this.eventListeners.has(eventType)) {
      this.eventListeners.set(eventType, []);
    }
    this.eventListeners.get(eventType).push(listener);
  }

  close() { this.isActive = false; }
}
```

生产环境推荐使用 [@microsoft/fetch-event-source](https://github.com/Azure/fetch-event-source)：自动处理断线重连、支持自定义请求头和 POST 请求，原理与上述代码一致。

### WebSocket vs SSE 选择

| 维度        | WebSocket        | SSE                     |
| --------- | ---------------- | ----------------------- |
| 通信方向      | 双向               | 单向（服务器 → 客户端）           |
| 协议        | ws\:// / wss\:// | HTTP（text/event-stream） |
| 自动重连      | 需手动实现            | 浏览器原生支持                 |
| 数据格式      | 二进制 + 文本         | 仅文本                     |
| 复杂度       | 较高               | 较低                      |
| HTTP/2 复用 | 不支持              | 支持                      |
| 适用场景      | 聊天、游戏、协同编辑       | 数据推送、监控、日志              |

选择 SSE：只需服务器推送，客户端发送用普通 HTTP 即可。
选择 WebSocket：需要双向实时通信。

### 性能实测对比（1000 并发用户）

| 方案        | 请求数/秒 | CPU | 内存    | 延迟     |
| --------- | ----- | --- | ----- | ------ |
| 短轮询（2s）   | 500   | 45% | 280MB | 1000ms |
| 长轮询       | 50    | 28% | 180MB | 100ms  |
| WebSocket | 0\*   | 12% | 95MB  | 15ms   |
| SSE       | 0\*   | 10% | 80MB  | 20ms   |

\*0 次指无轮询请求，只有初始握手和实际消息传输。

WebSocket 相比短轮询：CPU 降 1/4，延迟降 66 倍，内存降 3 倍。

### 生产环境要点

- 指数退避重连：`delay = min(1000 * 2^attempts, 30000)`，避免重连风暴。
- 先加载历史数据（HTTP），再连接 WebSocket，保证数据不丢。
- 心跳机制：定期发 ping/pong 检测连接存活。
- 连接状态管理：`disconnected → connecting → connected`，UI 随状态变化。
- 消息确认机制：重要消息需要 ACK，防止丢消息。
