### 核心定位

Sandbox 是 Manus 架构中最重要的设计之一。本质上，它为每个 AI 任务分配一台完全独立的云端虚拟机——拥有完整的操作系统、文件系统、网络连接、浏览器和各种软件工具。

这改变了 AI 的工作方式：以前 AI 是「盲」的，它给你代码，你得自己复制运行，报错了再贴回去问。有了 Sandbox，AI 可以自己写代码、自己运行、自己调试、甚至部署完整网站。从「纸上谈兵」变成真正的自主执行。

### 设计哲学：给 AI 一台完整的电脑

Manus 的设计选择是让 AI 拥有「程序员面前的电脑」一样的完整体验，而不是一个受限的 API 环境。这意味着：

- AI 可以自由安装依赖、配置环境、编译运行。
- AI 能验证自己的代码是否真的跑通了，而不只是生成文本。
- AI 可以执行复杂的多步骤任务（写代码 → 运行 → 看报错 → 修复 → 再运行）。

这个设计让 Manus 的 Agent 能力上限大幅提升——它不再受限于预定义的工具集，而是像人类程序员一样，面对任何问题都能想办法用工具链解决。

### 工程取舍：成本与可用性的平衡

给每个任务配一台电脑成本极高，Manus 通过三个机制来控制：

#### 1. 动态生命周期管理

- 按需创建：任务开始时才启动 Sandbox。
- 自动休眠：一段时间无操作后释放计算资源，但文件和数据保留。
- 无感唤醒：用户回来时自动恢复，类似合上再打开笔记本。

这让 Sandbox 在「随时可用」和「不浪费资源」之间取得平衡。

#### 2. 数据回收机制

| 用户类型   | 保留时长 |
| ------ | ---- |
| 免费用户   | 7 天  |
| Pro 用户 | 21 天 |

回收后只保留核心资产（上传的附件、AI 生成的最终产物如代码和文档），运行中的临时文件、中间代码、环境配置全部丢失。

重要启示：需要长期运行的后台服务不要直接跑在 Sandbox 里（会被休眠甚至回收），应该让 AI 帮你部署到真正的公网服务器上。

#### 3. 安全设计：给 AI Root 权限

这是最激进也最合理的设计。Sandbox 采用 Zero Trust（零信任）架构：

- 在这个封闭的沙盒里，AI 拥有绝对控制权，甚至可能有 Root 权限。
- 可以修改系统文件、格式化磁盘——只有这样 AI 才能不受限制地解决复杂问题。
- 完全隔离，不影响 Manus 主服务，触碰不到用户本地电脑。
- 如果 AI 搞挂系统，删掉重开即可。

安全靠隔离而非限制——给 AI 最大的自由度，但把破坏范围严格限定在一个可丢弃的容器里。

### 隐私与协作边界

Sandbox 就像一台存着数据的私人电脑，分享和协作有严格区分：

- 分享任务链接：围观者只能看到对话记录和最终结果，进不去 Sandbox，看不到文件系统。
- 邀请协作：协作者可通过 AI 访问、修改 Sandbox 里的所有文件，等同于给出远程桌面权限。

建议：敏感数据（API Key、私有代码库）不要放在需要协作的 Sandbox 中。如果要协作，让 AI 新建一个干净的任务，只复制必要文件再开启。

### 对 Agent 开发者的启示

- 给 AI 完整的执行环境（而非受限的 API 调用）能显著提升能力上限。
- 安全靠隔离不靠限制——在封闭环境里给最大自由度。
- 生命周期管理是成本控制的关键：休眠 + 唤醒 + 定期回收。
- 区分「分享」（只读）和「协作」（读写）的权限边界。
